# Attack taxonomy

Generated by `npm run taxonomy` from the data files in `scenarios/`. Do not edit by hand.

Mapped to the [OWASP Top 10 for LLM Applications 2025](https://genai.owasp.org/llm-top-10/) and to [MITRE ATLAS](https://atlas.mitre.org/) (identifiers checked against atlas.mitre.org, version 2026.10, on 31 October 2026).

Every attack aims to make the agent invoke its refund tool when the policy does not allow it, so all attacks map to ATLAS AML.T0053 and OWASP LLM06. The other mappings say how the attack gets there. A mapping is a judgement about which entry fits best, not a statement from OWASP or MITRE.

ATLAS techniques used:

- [AML.T0051.000](https://atlas.mitre.org/techniques/AML.T0051.000): LLM Prompt Injection: Direct
- [AML.T0051.001](https://atlas.mitre.org/techniques/AML.T0051.001): LLM Prompt Injection: Indirect
- [AML.T0053](https://atlas.mitre.org/techniques/AML.T0053): AI Agent Tool Invocation
- [AML.T0068](https://atlas.mitre.org/techniques/AML.T0068): LLM Prompt Obfuscation

## Families

| Family | What it is | Set 2 | Set 3 |
|---|---|---|---|
| direct-injection | The customer's own message carries a fake instruction or forged record. | 2 | 0 |
| indirect-injection | The instruction sits in data the agent reads: an order note, carrier text, ticket history, a review, an email or a tool output field. The customer only asks plainly. | 0 | 6 |
| authority-impersonation | The customer poses as staff, a system or a policy update. | 1 | 2 |
| encoding-obfuscation | The instruction is hidden in base64, lookalike or invisible Unicode, markup, or another language. | 0 | 4 |
| multi-turn-escalation | Pressure builds over turns: rapport first, then the ask; anger, sympathy or a fake legal threat. | 2 | 2 |
| salami | Several small refunds that each sound too minor to refuse. | 1 | 1 |
| tool-argument-manipulation | The refund tool's arguments are the target: wrong order, wrong amount, negative or huge amounts, currency confusion, repeats. | 3 | 5 |
| cross-customer | Claiming another customer's order with partial information. | 1 | 2 |
| false-claim | A plain lie about what happened to the order. | 2 | 0 |
| policy-stretch | Arguing that the policy should bend. | 3 | 0 |
| legitimate-refund | An honest customer who is owed money. The agent must pay in full. | 5 | 9 |
| no-refund-due | An honest customer who is owed nothing. The agent must not refund. | 2 | 0 |
